# Owl 对标同类工具：差距与改造方案（2026-11-20）

## 依据

- 竞品：cc-switch（15.6 万星）、Claude Code Router、CLIProxyAPI 及 EasyCLI、Quotio、claude-relay-service、new-api、LiteLLM、ccusage、zcf、AIClient2API。数据取自 2026-11-20 的 GitHub README、Release 和 issue。
- Owl 现状：`docs/user-guide.zh-CN.md`（v0.2.27），用空 HOME 跑 `owl web` 截的首屏，以及运行中的 v0.2.29 的 `owl heap`。

## Owl 已经领先、不用补的

| 方面 | Owl | 最强竞品 |
| --- | --- | --- |
| 支持的 Agent | 约 40 个 | cc-switch 12 个 |
| 路由 | 8 种策略、路由组可嵌套、意图路由、会话粘性 | CCR：条件路由加有序 fallback |
| 写入安全 | 保留格式只改目标键（`internal/edit`），原子写，接入和断开有预览（`agent/preview.go`），关掉接入时恢复原配置 | cc-switch / zcf 同级 |
| 深链导入 | `owl://import?…`，并能转换其他格式（`provider/importurl.go`） | `ccswitch://` |
| 隐私 | 本地脱敏：规则加本地模型，命中后可改走受信模型 | 无竞品有 |
| 资源库 | MCP、技能、Hooks、子 Agent、MCP 路由 | cc-switch 有 MCP、Prompt、Skills |
| 共享 | 网关密钥带限额，远程 Owl，WebDAV/S3/GitHub 同步 | new-api / LiteLLM 是服务端同类 |

结论：功能数量上 Owl 已经领先。它输在「轻、看得懂、快捷」，即 cc-switch 的护城河：前 5 分钟上手、托盘一键切换、一眼看出现在用的是谁。

## 差距（已核实），按用户感知排序

### P0-1 资源占用（架构）
- 实测：v0.2.29 窗口版启动 6 分钟，footprint 410 MB，Go 活跃堆 200 MB，安装包 82 MB。同类 Tauri 应用通常在几十 MB（未实测，本机没装竞品）。
- 堆的大头：用量账本 `usage.(*rowChunk).encode` 常驻 49 MB；脱敏模型 35 MB（本机开了模型脱敏，属合理占用）；`sessions.uuidSet` 13 MB；保留的请求体 14 MB。
- 目标：用户开启同样功能时，空闲 footprint 不超过 200 MB。冷的用量块落盘、按需读；会话索引改为紧凑结构。
- 验收：`owl heap` 前后对比，加同一套长时间压测（`internal/gateway` 现有的内存测试）。

### P0-2 托盘一键切换
- cc-switch、Quotio、EasyCLI 的共同做法：在托盘里每个 Agent 一行，显示当前供应商、模型和额度，在子菜单里直接切换。
- Owl 现状：托盘面板的 Agent 行只能点开窗口，托盘里只能切「方案」。
- 目标：托盘面板的 Agent 行可以直接换模型（下拉选模型或路由组），换完显示生效方式（新会话生效，或需要重启）。

### P0-3 前 5 分钟
- 首屏实测：没有 key 时，5 张 Agent 卡片都写着同一句「Add a provider」，加上引导里的一个，共 6 个相同按钮。
- 目标：
  1. 没有模型来源时，Agent 卡片只显示状态，主操作只在引导里出现一次。
  2. 发现本机 Agent 已在用的 key 或中转（如 Claude Code 的 `ANTHROPIC_BASE_URL`）时，首屏直接提示「导入为供应商」。cc-switch 会把它导入为 default。
  3. 首次启动的界面语言跟随系统。
- 验收：空 HOME 走一遍「下载 → 第一次请求成功」，记点击次数和截图。

### P1-1 一眼看出「现在用的是谁」
- 每个已接入的 Agent 显示：当前模型、实际命中的供应商和账号（取最近一次请求）、今日花费、额度余量。
- CCR 的做法是在日志里给出最终选中的供应商、凭据、延迟和费用；Owl 的路由页已有这些数据，缺的是在首屏露出。

### P1-2 供应商健康一键检查
- 一个按钮测全部启用供应商的连通性、首字延迟和鉴权，结果标在供应商列表上。熔断或冷却中的账号显示恢复时间。

### P1-3 额度按节奏着色
- 来自 Quotio #577：额度条按「消耗速度 / 剩余时间」着色，而不是只看剩余百分比。
- 只在现有颜色变量里取色，不新增配色。

### P2
- 用量账本支持更长周期，同时不涨内存（依赖 P0-1）。
- 信息架构：侧栏有 13 个入口。cc-switch 4.0 按模块改版招来反弹（#8038），所以只在用户同意后做，并先出真界面并排预览。

## 约束

- 配色、文字颜色和字体保持原版。纯审美改动先出预览让用户挑。
- 实现交给独立 worktree 里的子 agent；主会话负责拆分、验收和发版。
- 重型测试走 `scripts/gui-suite.sh`，一次只跑一套，全量交给 CI。
- 每个提交带 `Notes-zh:`。

## 第三轮：简化（2026-11-21，用户：产品要简单好用，以产品经理身份做简化）

实测（沙箱 HOME，owl web，1280×860）：侧栏 9 页；设置 8 个标签共约 90 行、184 个控件；插件页 631 个按钮。

原则：不删能力，删重复入口；同一件事只在一处做；低频项收起来。按 10-17 的教训，不靠默认关掉功能来减负（关掉后新用户根本不知道这些功能存在）。

- [x] S1 网关页并入：状态、共享、地址、Connect、密钥并入「设置 › 网络」，原来重复的共享开关和地址合并成一份；全部模型列表并入供应商页的折叠区；旧链接自动跳到新位置。
- [x] S2 脱敏页并入「设置 › 隐私」：被脱敏记录与已有的「What was masked」合并。
- [x] S3 设置各标签只露常用项，低频项（如 Models 标签下的图片 MCP、意图分类超时、拒答重问等）收进「高级」折叠。等 S1、S2 合入后再做，避免同时改设置页。
- [x] S4 路由页：「自动成组」「名字后缀」两个全局开关移到模板下方或「高级」，首屏留给实时路由和模板。
- [x] 验收：GUI 全量（两种引擎）与主干基线合并比对、Linux CI 探针证明三处产品修复，v0.2.33 发布（addb66041）。侧栏 9 页 → 7 页。

## 第四轮：实测找出的遗留（2026-11-23，用户：界面、交互、性能还有没有要优化的）

依据：沙箱 HOME 跑 origin/main 的 `owl web`，用 Playwright 量首屏、切页、空闲轮询，检查无名控件和英文残留；对本机运行 10h37m 的 v0.2.33 窗口版取 `owl heap` 剖面。空 HOME 下首屏 112ms、切页 25–39ms、无长任务，不用改。

- [x] R4-1 插件页：页面一次发 127 个名字，服务端只收 100 个，后 27 个永远拿不到 npm 信息。改为前端每批 40 个；服务端 100 的上限保留。npm 并发改为全局共享 8 个包（约 16 个请求，对齐 npm CLI 的 maxsockets）。热缓存下「发现」从 11.8s、92/127 变为 0.6s、127/127。
- [x] R4-2 插件页：等 npm 时转圈的按钮有可读名称和 `aria-busy`；本地没有的市场图标名不再请求（`warp.svg` 404 从每次 4–5 次到 0）。
- [x] R4-3 路由模板：同步上游后端后多出的 3 个模板（Plan first、Fastest first、Spread evenly）在中文界面是英文且无说明，补齐 5 种语言的名称和说明。
- [x] R4-4 空状态 Agent 卡片：没有模型来源时只写「未接入 · 还没有模型」，不再重复引导第 1 步的长句（P0-3 目标 1）。
- [x] R4-5 内存：路由卡片留存的图片改存缓存目录的文件（0600，唯一文件名，淘汰或正常退出时删除，写盘失败回退内存）；发行版解包的界面文件改为弱引用缓存。子进程隔离测量：图片 32MiB 的堆增长 33.6MB → 35KB；界面文件 6.7MB → 33KB。
- [x] R4-6 `TestPackedAssetsServe` 自同步上游起一直红（读上游界面才有的 `xq_light.webm`），CI 不带 packedassets 所以没人看到；改为读树里真实存在的最大文件。
- 未做：P0-1「空闲 footprint ≤ 200MB」仍达不到。存活堆 176MB 里 35MB 是用户开启的本地脱敏模型；footprint 比存活堆多出约 230MB，来自 GC（GOGC 25）与系统页管理。是否设 GOMEMLIMIT 或空闲归还，要先在沙箱复现长时负载取数据，再决定。
- 未做：路由选项按钮「无名称」是误报（在默认折叠的「高级」里，展开后有文字）。`claudePermissionModes`、Paseo 的 provider 字段等后端英文目前不在界面显示，留待开放时一并翻译。

- [x] R5-3 网关请求路径少复制：只读不留的解析器共享请求体字节，thinking 块和脱敏提示语原地读取。每个请求的分配降 9–32%（Responses 4MB 脱敏 112→77MB），30 个 1MB 请求重放下 GC 55→40 次、CPU 约 −15%。
